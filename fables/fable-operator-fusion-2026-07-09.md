# 算子融合

## 寓言

在一个繁荣的港口城市，有一座巨大的矿石精炼厂。精炼厂里有一台传说中的"熔炉之王"——这是整个城市最引以为豪的机器。每当炉火点燃，它能以前所未有的速度将成吨的矿石熔炼成纯金。

前两年，工厂斥巨资升级了熔炉的核心部件，据说新部件处理矿石的速度是旧部件的十倍。市长逢人就吹嘘："我们的熔炉是全天下最快的！"

但精炼厂的实际产能并没有提升十倍。最多也就快了两三倍。

精炼厂的日常工作是这样的：矿石从仓库搬出来，送到熔炉熔炼，熔好的半成品搬回仓库。然后取出，送去淬火。淬完火，又搬回仓库。再取出，送去打磨。打磨完，又搬回仓库。每一次搬运，都需要穿过长长的走廊，打开沉重的仓库大门，找到正确的货架，小心搬上推车，再原路返回。

城市里有个年轻人叫阿远，是精炼厂新来的学徒。他注意到一个奇怪的现象：熔炉明明升级成了天下第一，但精炼厂还是有大量的空闲时间——熔炉在等矿石送过来，淬火工位在等半成品送过来，打磨台在等工件送过来。

"熔炉这么快，为什么我们总是在等？"阿远问老师傅。

老师傅说："你不懂。我们这儿最重要的就是那台熔炉。问题一定是熔炉还不够快，或者你需要更多的推车。"

但阿远没有听从这个建议。他开始在工位旁边默默记录每一次工序的时间。

数据让他大吃一惊。熔炉虽然快得令人窒息，但**它只占了总时间的六成**。剩下的四成，全部花在了搬运上——矿石在仓库和各个工位之间的来回奔波。

更让他震惊的是另一个发现。精炼厂里有大量不需要过熔炉的矿石。这些矿石只需要几道简单的处理：清洗、酸浸、抛光。每一步本身只要几秒钟，但每步之间都要搬回仓库登记、分类、再取出。

阿远算了一笔账：清洗——三秒，搬回仓库——三十秒。酸浸——三秒，搬回仓库——三十秒。抛光——三秒，搬回仓库——三十秒。处理总共九秒，搬运却要九十秒。**真正做事的时间，只占一成。**

"仓库到工位，工位到仓库，仓库到工位……"阿远在纸上画着搬运路线，"我们花了所有精力让熔炉更快，但真正浪费时间的，是推车在走廊里跑。"

他壮着胆子去找厂长："我觉得问题不在熔炉。在搬运。如果我们把清洗、酸浸、抛光做成一条流水线——矿石从仓库出来一次，三个步骤在一个工位上连续完成，中间不回仓库——能不能省掉六成的时间？"

厂长皱起眉头："你这个想法……听起来不太规矩。"

"每道工序结束，东西得回仓库重新登记，这是我们一百年的规矩。"仓库主管也反对。

"规矩没错，"阿远说，"但当规矩本身成了最大的浪费，规矩就该改。"

阿远的方案被批准试验。精炼厂改造了一条流水线：矿石从仓库出来一次，依次通过清洗、酸浸、抛光三个步骤，直到最后成品才回仓库。

结果让所有人目瞪口呆——产能直接翻了一倍多。

但阿远并不满足。他又发现，要让这条流水线真正高效运转，不能像以前那样一步一步下达指令——"去仓库搬矿石""送去清洗""搬回仓库""送去酸浸"——而是要**提前把整条流水线的方案规划好**，画成一张完整的流程图，让每个环节无缝衔接。旧的指挥方式是走一步想一步；新的方式是先看全局，再一气呵成。

后来，有人问阿远："你的秘诀是什么？"

阿远笑了笑："大家都盯着那台最显眼的大机器，以为瓶颈就在那里。但升级了大机器之后，真正暴露出来的瓶颈，藏在所有人都忽略的地方——那些不起眼的小步骤之间，那些习以为常的来回奔波。停下来看看整条路径，你会发现最大的浪费不在'干活'上，而在'跑路'上。"

## 概念解析：算子融合（Operator Fusion）

在 GPU 上运行机器学习模型时，有一个反直觉的事实：**矩阵乘法占了 99.8% 的计算量，却只占 61% 的运行时间**。剩下的 39% 全花在了"搬数据"上——在 GPU 显存（VRAM）和各种计算单元之间来回读写。

这要归功于 2017 年之后 NVIDIA 推出的 Tensor Core。这些专用硬件单元让矩阵乘法的速度提升了 10 倍，但其他运算（加法、激活函数 ReLU、归一化等）的速度没变。这导致了一个新瓶颈：不是算不过来，而是数据搬不过来。

在 PyTorch 的默认"即时执行"模式下，每一步操作都是独立的：从显存读出数据 → 计算 → 写回显存。如果要对一个张量依次做"加法 → ReLU → Sigmoid"三步，数据要在显存里走三个来回。**算子融合**的做法是把这三步合并成一个 GPU 内核（kernel）：只从显存读一次，在寄存器里连续完成所有运算，最后写回一次。三趟变一趟，显存带宽消耗直接降为三分之一。

但融合无法在即时执行模式下实现，因为它要求你提前知道完整的计算图。这就是 `torch.compile` 的工作原理：它在 Python 字节码层面拦截你的代码，把整个计算流程捕获成一张图，然后自动找到可以融合的操作，生成优化后的内核。整个过程一行代码就能触发，但背后的原理就是这个——**减少数据搬运，比加快计算更关键。**
