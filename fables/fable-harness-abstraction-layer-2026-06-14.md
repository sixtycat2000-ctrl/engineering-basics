# 万国港

万国港坐落在大陆最大的河口，是天下货物的集散地。

每年来这里的船队不下百支——东洋的楼船吃水深、舱口大；北方的龙骨船甲板宽、索具多；西域的沙船轻巧灵便，却只有一道窄舱门。每支船队带来的不只是货物，还有各自的规矩：东洋船要三根缆绳靠泊，北方船要用铁锚锁扣，西域船竟要求码头工人在船舷两侧同时作业。

港口的调度官林舟为此头疼了三年。

起初，每次有新船队来访，他都得召集所有码头工人重新培训。"东洋船的第三根缆是刹车缆，千万不能先松。""北方船的甲板承重分三区，别在二区堆超过四吨。"培训手册越写越厚，工人越来越疲。更糟的是，有些船队来了一季就消失了，那些专门为他们学的操作法全成了废功夫。

林舟试过另一种办法：按船型分工。老张专门对接东洋船，老李专门对接北方船。可一旦老张请假，东洋船就只能干等。而且每当有全新船型出现——去年冒出来一种半船半筏的混合体——没人会操作，整个港口为此停摆了两天。

"我们不是在搬货，"林舟在日记里写道，"我们是在学一百种不同的搬货方式。"

转机出现在一个雨夜。

林舟坐在码头边看一艘东洋船靠岸。他注意到一件奇怪的事：不管来的是哪种船，码头工人们实际关心的只有几件事——货从哪里出、用什么工具吊、往哪里放、搬完后怎么确认。至于船上用的是绳索还是铁链、舱门是宽是窄，那是船员的事。

他拿出一张羊皮纸，画了一个方框。

方框里面只定义了五件事：**接驳口**（货从哪出）、**工具架**（吊货用什么）、**作业区**（货放哪里）、**签章台**（确认完成）、**通讯簿**（怎么和船员联络）。他把它叫做"**驳接协议**"。

然后他颁布了一道新规：从今往后，来万国港的每一支船队，必须在船舷上安装一个符合驳接协议的标准接驳口。安装的方式由船队自行决定——东洋人用他们的木工技术，北方向来精于铁器，西域人有自己的绳结花样。但接好之后，码头这端只认标准方框里的五件事。

老工人们一听就懂了。以前他们要学一百种操作，现在只学一种。东洋船来了，接标准口；北方船来了，接标准口；去年那种半船半筏的怪物来了——只要它装了标准口，照样能卸货。

最妙的是更换。某个船队的接驳口出了故障？换一支别的船队顶上，码头工人甚至不用放下手里的扳手。

三年后，万国港的吞吐量翻了五倍。

有人问林舟成功的秘诀。他指着码头上整齐划一的接驳口说："我不造船，也不学开船。我只做一件事——**让所有船都能用同一种方式和我说话。**"

---

💡 **概念解析：统一 Harness 抽象层（AI SDK 7 HarnessAgent）**

在 AI Agent 工程中，一个" Harness"管理的是模型调用之上的一切：技能系统（Skills）、沙箱环境（Sandboxes）、会话管理（Sessions）、权限流程（Permission Flows）、上下文压缩（Compaction）、运行时配置、子 Agent 编排。这些能力因平台而异——Claude Code 有自己的方式管理技能和权限，Codex 有另一套，Pi Agent 又不同。

AI SDK 7 的 HarnessAgent 做的事，和林舟的"驳接协议"完全一样：它定义了一套统一的接口，把不同 Harness 的能力差异封装在各自的适配器里。你的应用代码只和 HarnessAgent 打交道，不直接操作任何具体的 Harness。

这意味着两件事。第一，**写一次，到处跑**——你写的 Agent 应用代码可以在 Claude Code、Codex、Pi 之间自由切换，只需替换一行配置。第二，**面向未来**——三个月后出了新的 Harness，只要有人写出对应的适配器，你的代码一行不改就能用。

这本质上是**软件工程中抽象层原则**在 Agent 基础设施上的应用。就像 AI SDK 之前让开发者可以在不重写 Agent 的情况下切换模型（OpenAI、Anthropic、Google），现在它把同样的理念向上提升了一层——从切换模型，到切换整个 Harness。
