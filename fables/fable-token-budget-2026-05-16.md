# 旱季的水井

撒马尔罕城外有一座百年驿站，名叫"七泉"。所有要穿越大沙漠的商队，都得在这里补给水和饲料。

驿站的主人叫法蒂玛，是三代相传的水管家。七泉有一口深井，每天涌出的水量有限——不多不少，恰好灌满院子里的三只石槽。法蒂玛的工作，就是决定每支商队能取多少水。

每天清晨，法蒂玛会站在井边，打量陆续到来的商队。她有三个规矩。

**第一，看任务定水量。** 去隔壁绿洲的短途小队，一人一袋水足矣；但要去大马士革的长途驼队，每头骆驼都得灌满水囊。法蒂玛从不一视同仁——小任务给少，大任务给多，这是铁律。

**第二，派合适的人。** 短途的活儿，法蒂玛派年轻的学徒去引导，他们脚步快，喝水少，一天跑两三趟不在话下。但穿越大沙漠的商队，一定由经验最丰富的老向导陪同。老向导喝水多，但他们认得暗河与避风港，关键时刻能救命。

**第三，也是最重要的——法蒂玛从不等到井干了才着急。** 她在三只石槽的内壁刻了四道线。

第一道线在石槽的中间偏上。水面在这条线以上，一切如常，商队要多少给多少。法蒂玛管它叫"平安线"。

第二道线在三分之一处。水面降到这里，法蒂玛就开始精打细算了：几支去同一个方向的小商队，合并出发，走同一条路，水只带一份；各队的目的地信息压缩成一张总图，不用每队各画一张。有一回，三支小队本来要画三张地图，法蒂玛让学徒画了一张合成版，省下的羊皮纸钱都够再买两袋水。

第三道线接近槽底。水面降到这，法蒂玛就不再派老向导了。长途穿越计划一律暂停，所有商队只走短途，学徒带路，轻装出发。大沙漠？等明天吧。

第四道线几乎贴着槽底。水面到这里，法蒂玛只做一件事——把所有还在路上的商队叫回来，把已经准备好的物资清单整理好，交给商队首领，然后关上驿站的门。

"不是不做生意了，"她对不解的学徒说，"是今天的水只够交差，不够做好。硬撑着只会把骆驼渴死在半路上。明天井会再满。"

有一年秋天，一支来自波斯的豪华商队带着二十头骆驼浩浩荡荡到了七泉。为首的商人甩出一袋金子："我们要穿越大沙漠，全程路线，今天就得出发。"

法蒂玛走到石槽边看了看——水面刚好在第三道线上方。她把金子推回去，摇了摇头："今天只能送你们到第一个绿洲。剩下的路明天再走。"

波斯商人脸色变了："我付的是全程的钱！为什么不接？"

法蒂玛很平静："钱你可以留到明天花。但水，今天用完了就没了。我把水全给了你，后面十支小商队——那些只去隔壁绿洲送信的、送药的、接孩子的——就都得渴死在路上。你以为你在买水，其实你在抢别人的命。"

波斯商人沉默了很久，最终收回了金子。第二天，井水重新涌满，法蒂玛派了最好的老向导，他顺利穿越了大沙漠。

后来这个波斯商人逢人就说："法蒂玛不是最好的向导，但她是最懂水的管家。在她的驿站，没有一支商队渴死过。"

## 💡 概念解析：Token Budget（令牌预算）

这则寓言讲的是 Multi-Agent 系统中的 **Token Budget**——令牌预算管理。

故事里的"水"就是 Token，是大模型推理时消耗的计算资源。每一轮对话、每一次工具调用、每一个 Agent 的思考过程，都在消耗 Token。就像驿站的井水一样，Token 不是无限的——它有成本上限，也有实际约束。

法蒂玛的三条规矩对应 Token Budget 的三层核心策略：

**1. 看任务定水量 → Model Routing（模型路由）。** 不是所有步骤都需要最贵的模型。简单任务（分类、摘要）用小模型，复杂任务（推理、规划）用大模型。就像短途派学徒、长途派老向导。

**2. 合并商队、压缩地图 → Context Compression（上下文压缩）。** 当预算紧张时，把多个 Agent 的历史信息压缩成摘要，而不是保留完整原文。既省空间又不丢关键信息。

**3. 四道刻度线 → Budget 分级降级。** 这是 Token Budget 最精妙的部分：绿区（>50%）正常执行；黄区（20%-50%）开始压缩上下文、合并步骤；红区（5%-20%）切换小模型、跳过深度推理；熔断区（<5%）强制收束，返回已有结果。每一级都是主动选择，而非被动耗尽。

关键区别在于：Token Budget 是**实时调度**，不是事后算账。法蒂玛不是在日落时分数空水袋，而是每时每刻盯着水位线做决策。生产级 Agent 系统也一样——在执行过程中实时监控 Token 消耗，动态调整策略，确保系统永远不会在"半路上渴死"。
