# 📖 每日工程寓言 — 编排税

## 忙碌的织工

在纺织王国里，有一位织工名叫林远。他有一间不大的作坊，一台老旧的手摇织布机，每年能织出二十匹布。日子虽不富裕，但每匹布的质量他都心中有数——哪里松了一针，哪里配色不够均匀，他闭着眼睛都能指出来。

有一天，国王颁布了一道命令：所有织工必须提速，产量翻倍，否则取消执照。林远愁了一整夜，直到他在集市上看到了一种新奇的东西——自动织布精灵。

这些精灵不是什么魔法生物，而是发条驱动的机械小木偶，每个只要上满发条，就能按照预设的图案自动织布。最关键的是，**启动它们几乎不花什么力气**。一个铜币上一次发条，一个精灵就能嗡嗡嗡地干上半天。

林远心动了。他卖掉了家里那头耕地的老牛，买回来五个精灵。他把作坊改造成上下两层：五个精灵在下层日夜不停地织，他在上层——用他的话说——"总控全局"。

头三天，林远觉得自己简直是天才。五个精灵同时嗡嗡运转，产量肉眼可见地翻了好几倍。他每天早上起来巡视一圈，摸摸布匹，觉得一切尽在掌握。他在酒馆里对别的织工说："你们还在用手摇？我已经进入精灵时代了。"

---

## 堆积的布匹

第七天，问题开始出现了。

精灵甲织出了一匹格子花纹的布，但格子歪了三度。精灵乙织了一匹条纹布，条纹的间距在第三米处突然变了——发条松弛了。精灵丙倒是忠实地执行了图案，但它织的是上一批的旧图案，因为林远忘了给它换指令卡。

林远试图一一修复。他先检查了精灵甲的校准——花了半小时。然后转向精灵乙，需要先回忆乙之前织的条纹间距标准是什么——又花了四十分钟。等他走到精灵丙面前，脑子里已经装了甲的格子和乙的条纹，现在又要切换到丙的图案逻辑。他发现脑子像灌了浆糊。

"没关系，"他对自己说，"产量上去了就行。"

第十四天，作坊里堆了四十多匹布，但只有六匹通过了林远自己的检查。剩下的要么图案错位，要么配色偏差，要么底边脱线。更糟糕的是，林远发现自己已经记不清哪匹布是哪个精灵织的——它们长得都差不多，但问题各不相同。

他每天早上要做的事情变成了这样：先花十五分钟回忆昨天检查到哪一匹了，然后逐匹拿起、展开、目测、折叠、标记。有时候他刚标记完一匹"格子偏移"，去看下一匹条纹布时，脑子里还残留着格子的画面，导致他差点误判条纹的间距。

他越来越忙，但产出的合格布匹却没有增加。他每天累得筋疲力尽，在酒馆里却只能说："今天又检查了十二匹，有三匹勉强能用。"

别的织工问他："你不是有五个精灵吗？怎么合格率这么低？"

林远答不上来。他确实很忙——比以前任何时候都忙——但忙碌和产出之间的联系，似乎断了。

## 织工的顿悟

第二十一天，林远的一个老朋友——一个在王家织造局当了二十年质检官的人——来作坊看他。

老质检官看了看堆满屋子的布匹，又看了看林远布满血丝的眼睛，问了一个问题："你现在每天花多少时间在织布上？"

"织布？"林远愣了一下，"我一个钟头都没花在织布上。我全花在……检查精灵的产出上。"

"那就是了。"老质检官拉过一把椅子，"你知道你犯了什么错吗？你把自己变成了一个——怎么说呢——**只有一个通道的检查站**。五个精灵同时往你这里送布，但你看布的速度并没有变成五倍。你还是一次只能看一匹。每切换一次，脑子就要清空重来。你花在切换上的时间，比检查本身还多。"

林远沉默了。

"启动精灵便宜，"老质检官继续说，"一个铜币，一拧发条，它就嗡嗡跑起来。但是**检查精灵的活儿，贵得要命**。贵在哪儿？贵在你每次重新进入一个精灵的上下文，都要重新理解它织了什么、应该织什么、偏差在哪里。这不是拧发条能解决的。"

"那我该怎么办？"林远问，"砍掉精灵？"

"不一定要砍。但你得想清楚一件事：**你才是瓶颈，不是精灵**。"

---

## 五条规矩

老质检官临走前，给林远留下了五条规矩：

**第一，别让精灵跑得比你看得快。** 你一天能仔细检查几匹，就让精灵一天产出几匹。多余的产出不是资产，是负债——它们堆在那里等你检查，每一匹都在消耗你的注意力。

**第二，把活儿分两堆。** 一堆是"闭着眼也能检查的"——图案简单、标准统一的布，让精灵跑，你批量过。另一堆是"需要你真正动脑子判断的"——比如复杂的双面织、客户定制的特殊纹样——这种活别并行，你自己织，或者一次只让一个精灵做。

**第三，集中检查。** 别每隔半小时就跑去看一次。让精灵先跑完，你一口气检查完所有产出。一次进入检查状态的成本，远低于分五次进入的成本。

**第四，让精灵自证清白。** 教精灵自己跑基本质检——用尺量间距、数格子数、拉一拉边角看牢不牢。你只需要处理精灵自己搞不定的那两成问题。

**第五，把你最好的时间留给判断，不是留给巡视。** 真正值钱的是你坐在那里、安静地、仔细地判断一匹布好不好。别把这种最重要的工作塞在所有琐碎检查的间隙里。

林远听完，问了一个问题："那精灵到底有用吗？"

"有用，"老质检官说，"但它们有用的前提是你理解了一个道理——**有时候最高明的做法，是关掉所有精灵，坐下来好好想明白一匹布该怎么织。** 精灵帮你干活，但判断什么是值得干的活、干得好不好的那个，永远是你自己。"

林远送走了老朋友，回到作坊。他关掉了三个精灵，留下两个——一个做批量标准布，一个做简单定制。他把省下来的时间，拿去研究了一种新的织法。

三个月后，林远的作坊只有两个精灵在运转，但合格布匹的产量，比五个精灵时代多了一倍。

## 💡 概念解析：编排税（Orchestration Tax）

**编排税**是 Addy Osmani 提出的一个概念，描述的是在使用多个 AI Agent 协同工作时，**人类成为系统瓶颈**的隐性代价。

核心矛盾在于一个不对称：**启动 Agent 的成本极低**（一条 prompt 就行），但**关闭循环的成本极高**（验证、判断、合并冲突解决）。Agent 可以并行运行，但你的认知带宽是单线程的——你可以同时启动 8 个 Agent，但 reviewing 它们的产出时，你还是一个一个看。

这个概念用了三个技术类比来解释：

- **GIL 类比**：你就是 Python 的全局解释器锁。很多线程（Agent）在跑，但需要真正判断的时候，只有一个锁——你拿着它。
- **Amdahl 定律**：并行加速的上限取决于串行部分的比例。在 Agent 工作流中，串行部分就是"人的判断"。8 个 Agent 不会让判断更快，只会让等待判断的队列更深。
- **优化谬误**：加 Agent 优化的是原本就不是瓶颈的东西。真正的瓶颈是 review 步骤——系统的吞吐量等于 review 步骤的吞吐量。

常见的失败模式包括：草率的代码审查、认知投降（不形成自己的判断就接受 Agent 输出）、以及"仪表盘满满但主干分支空空"的隐形生产力幻觉。

**应对策略**的核心思想是：把你当作系统的瓶颈来设计，而不是假装你的认知带宽可以无限扩展。保护你做判断的最佳时间，而不是把它塞在碎片化的检查间隙里。

> 有时候最高杠杆的做法，是关掉所有 Agent，坐下来好好想清楚一个单一问题。编排不是真正的工作，它是围绕工作的开销。
