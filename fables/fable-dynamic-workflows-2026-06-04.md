# 裁判所的三个幽灵

> 一个天才裁判如何被懒惰、自恋和遗忘逐个击溃，又如何靠一整套分工系统绝地反击。

---

阿成是海门城邦的首席裁判。

城邦刚建的时候，案子不多，阿成一个人全扛下来了。他天资聪颖，记忆力惊人，同时记住十几个案子的细节也不在话下。商人们都说："海门有个神仙裁判，什么案子到他手里，三句话就能断清楚。"

但城邦渐渐繁荣了。

港口贸易纠纷、邻里地界争端、海上事故调查、治安事件……每天堆到阿成桌上的卷宗有五十多份。他发现自己开始犯一些奇怪的错误。

第一个错误是**偷懒**。安全审查报告有五十份，他仔细审了前二十份，后面的扫了一眼就签了"合格"。他不是故意的——审到第三十份的时候，注意力就像漏水的桶，怎么也提不起来。

第二个错误更隐蔽。城邦议会要求他每月做一次"裁判质量自查"，回顾自己近期的判例。阿成翻完卷宗，满意地点点头——判得挺好，没什么需要改的。可旁观的书记官知道，上个月那个码头租赁案明显判偏了，阿成自查的时候却写道"裁决合理，维持原判"。人对自己的判断有一种温柔的天性，连阿成这样的天才也不能幸免。

第三个错误最可怕——**遗忘**。到年底的时候，阿成对年初亲自宣读的一条法令已经记不清了。"禁止三桅帆船在东码头停靠"，他说成了"双桅"。结果一桩新案子里，他把完全适用的法条记错了，判了个南辕北辙的结论。工作内容越多、时间越长，边界条件和约束就越容易被冲刷干净。

首席裁判阿成，正在被三个看不见的幽灵逐个吞噬：**懒惰、自恋、遗忘**。

老总督终于坐不住了，请来了一位名叫方图的管理大师。

方图看了一眼裁判所的运作，只说了一句话："问题不在裁判的能力，在于你让一个人同时做所有事。"

他设计了一套**六种分工机制**，每种针对不同的案件类型：

**第一种：先分类再行动。** 设立分类台，新案件进来先由分类官判断类型——海事纠纷、土地争端、商业欺诈——然后分流到专业裁判。阿成不需要猜每个案子该用什么方法，分类官比他更擅长这件事。

**第二种：分头出击，聚合收网。** 大规模批量任务比如审查一百艘船的安全——不要交给一个人。五个裁判各审二十艘，审完后全部交到总编撰官手里做综合报告。总编撰官是一道**屏障**，必须等所有人都交齐了报告才开始汇总，谁也不能跳过谁。

**第三种：对立审查。** 这是最关键的一招。每个裁判审完案件后，**不允许自己评价自己**。方图设立了"对立裁判"制度：审查官说"合格"的，对立裁判要找出它为什么不合格；审查官说"不合格"的，对立裁判要验证它是否真的有问题。"人对自己的判断天生偏袒，"方图说，"唯一的解法是让另一个人站在对立面。"

**第四种：广撒网，精筛选。** 对于征集类工作——比如征集新城门的设计方案——先广泛征集，然后由筛选委员会根据明确的标准淘汰不合格的、合并相似的，只留高质量的设计进入终审。

**第五种：对决赛制。** 当几个方案都很好，很难打分排名时，让两个方案直接比拼，由第三方投票，胜者晋级，败者淘汰。比到最后只剩一个。"成对比较比绝对打分更可靠，"方图解释道，"人很难给一个设计打 8.3 分还是 8.7 分，但很容易说出左边这个比右边好。"

**第六种：查到没线索为止。** 对于不知道工作量多大的事情——比如"找出所有走私线索"——派一组人去查，查到新线索就继续深挖，查不到新东西就停。不需要事先估算要查多久，干到干不动为止。

阿成最初不服气："这不就是多雇几个人吗？能比我一个人做得好？"

方图没有反驳，只列了一组数字："你一个人的时候，五十个案子只做了二十个；三个案子判错了你自己不知道；第五个月忘了第一个月立的法。阿成大人，您管这叫'做好'？"

六个月后，裁判效率翻了四倍，错误率降了九成。阿成不再是那个疲惫的独行者，他成了审判长——制定标准，监督流程，不再亲自审每一个案子。

城邦的商人们又有了新的说法："海门有套神仙系统，案子进去，出来的时候连错别字都被挑干净了。"

没人再提起阿成一个人的名字。但每个商人都知道，这套系统叫什么——

它叫**动态裁判制**。

## 💡 概念解析：Dynamic Workflows（动态工作流）

当 AI Agent 在单个上下文窗口中处理复杂任务时，会遭遇三种系统性失败模式：

- **Agentic laziness（懒惰）**：长任务做到一半就停下来，声称已完成（50 项审查只做 20 项）
- **Self-preferential bias（自恋）**：自我验证时天然偏袒自己的输出，看不到自己的错误
- **Goal drift（遗忘/目标漂移）**：上下文压缩后，边界条件和关键约束被冲刷丢失

Claude Code 的动态工作流通过多 Agent 编排来对抗这三种失败。它让 Claude 根据任务即时编写一个 JavaScript harness，用 `spawn()` 创建隔离的子 Agent，并提供了六种编排模式：

1. **Classify-and-Act** — 分类器路由到不同专业 Agent
2. **Fan-out-and-Synthesize** — 分头并行，屏障聚合（barrier pattern）
3. **Adversarial Verification** — 执行 Agent + 对立验证 Agent，消除自我偏袒
4. **Generate-and-Filter** — 批量生成 → 标准筛选去重
5. **Tournament** — 多 Agent 同任务竞争，配对评决赛出最优
6. **Loop Until Done** — 循环执行直到停止条件满足

核心思想：不让一个 Agent 做所有事，而是通过结构化的多 Agent 协作，用隔离的上下文窗口和明确的分工来抵消单个 Agent 的系统性弱点。每个任务一个 harness，harness 由 Agent 自己编写——这就是"动态"的含义。
