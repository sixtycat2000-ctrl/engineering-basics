# 把代码交给翻译官

在一个古老的王国里，国王决定修建一座前所未有的宏伟图书馆。图纸极其复杂——十万根梁柱，每根的角度、材质、承重都不同。国王召集了王国里最好的建筑师们来建造。

建筑师们很优秀，但速度太慢。一个人一天最多完成三根梁柱的图纸。而图书馆需要十万根。按这个速度，图书馆要三百年才能建完。

于是国王请来了一位神秘的翻译官。这位翻译官有一个特殊能力：你把建筑的意图用语言描述给他，他就能在石板上刻出精确的施工图。而且他的速度快得惊人——一天能刻出一千张图纸。

翻译官刻出来的图纸，每一张都看起来完美无缺。尺寸精确，标注清晰，格式统一。但老建筑师们隐隐不安。

"我们必须逐张检查。"首席建筑师说。

翻译官笑了笑，没有说话。

第一天，他交出了一千张图纸。老建筑师们从早审到晚，审了八十张。第二天，又来了一千张。八十张也审不完了。到了第七天，积压了七千张图纸，审过的不到五百张。

工地停工了。不是因为没图纸，恰恰相反——图纸堆积如山，但每一张都"还没被审过"，所以没人敢用。

"这不是速度的问题，"一个年轻的工匠说，"是我们的检查方式根本不适合他。"

她提出了一个大胆的想法："我们不再逐张审他的图纸。我们在建造之前，设置三道关卡。"

**第一道关卡在翻译官动笔之前。** 她给翻译官写了一套极其严格的规则手册——不是"请画出美观的拱门"，而是"拱门跨度不得超过四米，石料密度必须在2.4-2.7之间，承重安全系数不低于1.5"。翻译官必须在这套规则之内创作，就像诗人写十四行诗——形式本身就是约束。

老建筑师们皱眉："这不是限制他的创造力吗？"

"不，"她说，"这正是编译器做的事。你不会觉得类型系统限制了程序员的创造力，你只会觉得它把错误挡在了门外。"

**第二道关卡在图纸刻好之后、施工之前。** 她设计了一套自动化验证装置：每张图纸刻完后，放进装置里，装置会模拟这座梁柱在各种极端条件下的表现——暴风、地震、百年沉降。图纸只要有一处不达标，立刻退回重刻。

"但翻译官不是每次都给出同样的答案，"有人指出，"同一个意图，他今天刻的图和明天刻的可能细节不同。"

"所以验证装置必须比人工审图严格十倍。"她平静地说，"他的速度是一千张一天，我们有的是时间让装置反复验证每一张。问题不是验证的成本太高，而是我们还没认真对待验证这件事。"

**第三道关卡在建筑本身。** 她要求每根梁柱安装时都先用轻质替代材料试装，观测一周，确认无异常后再换上正式石料。而且每十根梁柱有一根装有预警传感器——一旦承重出现异常，整片区域立刻锁定。

"这不就是金丝雀发布和监控吗？"一位年迈的建筑师突然说，"我们三十年前就会这些了。"

"对，"她说，"工具一直在那里。我们只是从来没用在一个一天能产出千张图纸的翻译官身上。"

三个月后，图书馆封顶。十万根梁柱，零事故。

国王问她："你信任翻译官吗？"

她想了想，说："我不信任翻译官。我信任那三道关卡。就像我们不信任编译器，但我们信任类型系统、测试套件和部署流水线。"

她顿了顿，又说："以前我们信任的是审图人的眼睛。现在我们信任的是一套工程体系。变的是信任的位置，不变的是对正确性的追求。那些害怕闭灯工厂的人，不是因为他们不关心正确性——他们只是还没看见正确性搬到了哪里。"

国王又问："那审图人以后做什么？"

"他们去做最重要的事——设计规则手册、改进验证装置、决定图书馆应该长什么样。"她说，"审图从来不是目的，造出好的建筑才是。"

## 💡 概念解析：把 Agent 代码输出当作编译器输出

Skip Labs 的 Hugo Venturini 在 "Treat Agent Output Like Compiler Output" 一文中提出了一个核心洞察：我们对"无人值守代码库"（lights-out codebase）的恐惧，本质上不是因为 AI 写的代码不可靠，而是因为我们还没有建立起让这种可靠性可信赖的基础设施。

**编译器类比是这个概念的核心。** 没有人会逐行审查编译器输出的汇编代码。不是因为编译器没有 bug（历史上出过灾难性的编译器 bug），而是因为我们建立了一套完整的验证体系：类型系统在编译前约束正确性，测试套件在编译后验证行为，fuzzing 和形式化方法探索边界情况，金丝雀发布和监控在生产环境中兜底。信任被分配到了流程中，而非人工审读中。

**三层验证模型：**

1. **上游约束（编译前）：** 编译器有类型系统和形式化契约；当前 AI Agent 只有 prompt。需要建立 Agent 可验证执行的形式化规格层（TDD、契约测试、设计即规格）。
2. **验证层（编译后）：** 编译器是确定性的（同源同果），Agent 不是——它会以 50 倍速度产出"看起来对但微妙地错"的代码。因此测试套件必须比人工审查时代的测试严格一个数量级。AI-checks-AI 管线必须成为一等公民的 CI 基础设施。
3. **下游安全（生产环境）：** 金丝雀部署、Feature Flag、可观测性——工具已存在，只是还没有成为处理 Agent 代码变更的习惯性实践。

**关键结论：** 编译器没有让我们停止关心正确性，它只是把正确性执行的地点挪了。对 Agent 代码也一样——问题不是"要不要信任"，而是"有没有建好让信任合理的工程体系"。
