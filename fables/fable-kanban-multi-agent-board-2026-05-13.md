📖 每日工程寓言 — 多Agent看板（Kanban Multi-Agent Board）

老吴是南城最大的印刷厂老板。他的厂子有个怪规矩：所有工人不进车间。

准确地说，车间是个巨大的空房间，中间放了一块黑板。工人们从不到里面碰面——他们只跟黑板打交道。

每天早上，老吴站在黑板前，把今天的活拆成一个个任务卡片，钉到黑板上。每张卡片写着任务名称、要求、交给谁做。卡片下面还有一个状态框，初始状态写着"等待"。

比如今天来了个大单：给一家出版社印一套百科全书。老吴拆了六张卡片——

"查资料" → "校对事实" → "写初稿" → "排版" → "审校" → "印刷"

每张卡片指定了不同的工匠：研究员老陈负责查资料，校对员小王负责校对，编辑阿芳负责写稿……老吴自己呢？他什么都不做。他只负责拆任务和钉卡片。

这个怪规矩是老吴花了三年血泪换来的。

三年前，老吴的厂子不是这样的。那时候他喜欢"当面交代"——把所有人叫到一起，他口头派活，工人们当面领任务、当面交活。听起来很高效，但问题很快就来了。

有一次，排版工小刘正在干活，突然家里有急事，放下东西就走了。他手上的活干到一半，没人知道进度，也没人接手。等他三天后回来，整条流水线都卡在那儿了。老吴气得摔了杯子。

"你走了，你的活怎么办？"

"我以为别人会接着干……"

可谁也不知道他干到哪了。那次的百科全书项目延迟了两周。

还有一次更离谱。老吴自己也是急性子，有一次他看校对员小王太慢，就自己上手改了几页稿子。结果小王不知道老吴改过了，又按旧版本继续校对，两个人各改各的，最后交上来的东西自相矛盾。印刷出来之后被客户退了回来。

老吴痛定思痛，决定彻底改规矩。

**第一：所有任务必须上黑板，不准口头传达。** 每张卡片有唯一编号、状态、负责人的名字。谁干了什么、干到哪了，一目了然。

**第二：状态必须流转，不准跳过。** 卡片只有固定的几种状态——"等待"→"就绪"→"进行中"→"完成"。每个工匠只能改自己名下的卡片。如果前面的卡片还没"完成"，后面的卡片就永远是"等待"，谁也领不走。

这个规矩立下来之后，神奇的事情发生了。

研究员老陈查完资料，把卡片翻成"完成"，顺手在卡片背面写了一段话："第47页的地质数据有两个版本，请校对员注意。"校对员小王领到任务时，翻过卡片就看到了这条留言——他不需要当面碰头，信息已经跟卡片走了一路。

后来老吴又加了一条规矩：**如果工匠遇到问题，可以把卡片翻成"阻塞"，在背面写上问题。** 这时候老吴或客户就会来看，写下回答，再把卡片翻回"就绪"。工匠重新领走继续干。

有一次排版工连续三次把卡片搞成"阻塞"，老吴看了看黑板，叹了口气——他给这个任务加了个"三次阻塞自动暂停"的规矩。第三次阻塞后，卡片自动锁住，必须老吴亲自来解锁。后来他发现这个规矩救了命：有一个任务本身就写错了，不是工匠的问题，自动暂停避免了更多返工。

最妙的是有一天夜里下暴雨，厂子停电了。所有工匠被赶回家。第二天来电后，所有人回来一看黑板——每张卡片还在原来的位置，状态一个字没变。研究者老陈的卡片还是"进行中"，他坐下来接着昨天的进度继续查，好像什么都没发生过。

有个新来的学徒问老吴："师父，你站在黑板前面什么都不干，凭什么你是老板？"

老吴笑了："我什么都不干，但谁都离不开我。因为我把活拆对了，把人排对了，把规矩定对了。车间里没有一个工人见到另一个工人，但百科全书就是这么印出来的。"

他指了指那块黑板："这就是整个工厂。其他都是空房间。"

💡 概念解析：多Agent看板（Kanban Multi-Agent Board）

这则寓言讲的是 **Kanban Multi-Agent Board**——一种用于多个AI Agent协作的持久化任务看板架构。它不是把多个Agent塞进同一个进程里互相调用，而是让所有Agent通过一块共享的"黑板"（SQLite数据库）异步协作。

核心设计思想有几层：

1. **持久化状态机**：每个任务像一张卡片，有严格的状态流转（todo → ready → running → done）。状态存在数据库里，断电不丢、崩溃可恢复——不像内存中的函数调用，进程一死就没了。

2. **依赖自动推进**：子任务在前置任务全部完成后才变成"就绪"，不需要人工催促。就像研究员翻完卡片，校对员的任务自动解锁。

3. **命名身份与持久记忆**：每个Agent有名字和角色（研究者、编辑、工程师……），不是匿名的临时工。他们带着记忆上岗，下次领任务时还记得上次做过什么。

4. **人类随时介入**：Agent可以"阻塞"任务，等待人类决策；人类可以留言、解锁、重新派发。协作不只是Agent之间的事，人是板上的一员。

5. **编排者不干活**：Orchestrator只拆任务、排依赖、派工匠，自己绝对不上手——这是用制度（disabled toolsets）保证的，不是靠自律。

6. **熔断保护**：连续失败的任务会被自动暂停（circuit breaker），防止错误像雪球一样越滚越大。

一句话总结：**当协作需要跨越时间、跨越角色、跨越崩溃与重启，就不要用电话叫人，用黑板留条。**
