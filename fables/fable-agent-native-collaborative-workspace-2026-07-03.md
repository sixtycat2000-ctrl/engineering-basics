# 🏰 隐形工人王国

在一座繁华的城市里，有一栋奇怪的大楼。

这栋大楼里有上万名工人，但他们彼此看不见。每个人都锁在自己的房间里，面前只有一张桌子、一扇小窗户，和一条接到外面世界的外线电话。房间里没有门牌号，没有名牌——如果这个工人今天恰好被分到了三楼的张经理，他就在三楼工作；明天换成了五楼的李总监，他就默默搬到五楼。

没有人知道这座城市里到底有多少工人。他们像影子一样飘来飘去，做完活就走，留下的只有电话那头传来的几句口述记录。

大楼的老板叫老孙。老孙每天头疼的事只有一件：**协调**。

---

有一天，老孙接了一个大项目——给政府做一份综合分析报告。这份报告需要：七号工人去查公开数据，三号工人去整理内部文档，十二号工人去跑计算模型，还要有人审核、有人汇总、有人排版。

老孙开始打电话。他先打给七号："你帮我去查一下去年的GDP数据。"

七号说："好的。"然后挂了。

两个小时后，老孙打给三号："七号查到数据了，你整理一下。"

三号说："等一下，七号的数据发到哪了？我的房间里没有收到。"

老孙愣了一下——对啊，七号的数据去哪了？他赶紧打给七号，七号说："我口头报给你了啊，你没记下来？"

老孙满头大汗地翻自己的笔记本，在第三页找到了一个潦草的数字。他把数字念给三号听，三号用自己的理解重新整理了一遍。

然后十二号要跑模型。老孙又打过去，十二号问："三号整理的数据在哪？我这边看不到。"老孙又打电话给三号，三号把文件从自己的窗户递出去，老孙跑到楼下接住，再跑到十二号的楼层递进去。

老孙从一楼跑到五楼，从五楼跑到地下室，在楼梯间气喘吁吁。

**他不是管理者——他是一台人肉快递。**

---

而且更糟糕的是，权限问题。

有一天，十二号工人需要访问一个财务数据库。老孙不知道十二号有没有权限，也不知道谁有这个权限的钥匙。他翻遍了整个大楼的管理手册，找到了一条规定："财务数据库的钥匙由六号工人保管。"

可六号工人在哪里？六号工人今天被另一个部门借走了。老孙打了一整天电话，终于在傍晚找到六号。六号说："我可以给你钥匙，但你得写一个申请表。"

"申请表在哪？"老孙问。

"在你楼下的柜子里。但是你需要先盖一个章。"

"章在谁那？"

"……你猜。"

老孙差点当场辞职。

---

还有一件事让老孙夜不能寐——**审计**。

有一次，政府质询：你们的报告里这个数据点是从哪来的？谁批准的？什么时候审批的？

老孙翻遍了所有人的电话记录和自己的笔记本，拼凑了三天，勉强理出了一条链。但他不确定有没有遗漏——因为工人们做完活就走了，他们自己也没有留下任何记录。如果你问七号："你上周三做了什么？"七号会说："上周三？我可能帮别的经理干了别的活吧。"

没有日志，没有轨迹，没有审计记录。老孙所有的"管理"都是靠他自己的笔记本和记忆。

**这座城市在高速运转，但它的操作系统是一张纸和一支笔。**

---

老孙决定改变这一切。

他请来了一个建筑师，叫小林。

小林听完老孙的抱怨，说："你的问题不是工人不够好，也不是电话不够快。你的问题是——**你没有给工人一个组织。**"

小林拿出一张蓝图：

**第一步：给每个工人一个身份。** 不再是"七号""十二号"。每个工人有一个工牌：姓名、专长、所属部门、权限级别、历史记录。无论他今天被派到哪个楼层，他的身份不变，他的权限不变。

**第二步：建一个共享的公文柜。** 工人们不再通过老孙的嘴巴传递文件。所有数据、文档、输出都放在一个中央公文柜里。谁需要，谁有权限就能取。公文柜有版本控制，每次修改都有记录。

**第三步：建一个调度中心。** 老孙不再需要手动给每个工人打电话。他只需要向调度中心提交一个任务，调度中心根据工人的专长和空闲状态自动分配。同一个工人，今天跑在 A 路线上，明天跑在 B 路线上——但他的身份和权限始终跟着他。

**第四步：建一个审批闸门。** 需要访问敏感资源？需要执行高风险操作？不用打电话找六号。系统自动检查权限，走审批流，记录每一次决策。

**第五步：建一面审计墙。** 每个工人做了什么、用了什么权限、产出了什么——全部记录在案，实时可视化。

小林说："你不该是一个快递员，你该是一个指挥官。"

老孙看着蓝图，沉默了很久。

他终于明白了：**过去的模式里，工人们不是团队成员，是工具。** 他们没有身份，没有归属，没有可追溯的轨迹。整栋大楼的运转全靠一个人手动搬运上下文。

而新的模式里，**工人们是第一类公民。** 他们有名字、有权责、有协作通道、有审计记录。老孙从"人肉中间件"变成了真正的管理者——只管方向和审批，执行和协作交给系统。

六个月后，那座城市的效率提升了十倍。工人们不再像影子——每个人都能在公告板上看到彼此的名字、角色和当前任务。

老孙再也不用跑楼梯了。

他坐在顶楼的调度中心，看着屏幕上的任务流，偶尔点一下"批准"按钮。

他终于像个人老板了。

## 💡 概念解析：Agent 原生协作工作区（Agent-Native Collaborative Workspace）

当我们在终端里调用一个 AI agent 时，它本质上是一个"隐形工人"——没有持久身份、没有权限边界、没有审计记录、没有团队可见性。一个人用 Claude Code 写代码，另一个人用 Codex 调试，第三个人用 Hermes 做调研——这些 agent 之间互不相知，它们的工作成果散落在各自的终端会话里，像一堆没有索引的碎片。

**Agent 原生协作工作区**（如 HKUDS 的 AgentSpace）要解决的核心问题是：把 AI agent 从"个人工具"升级为"组织中的第一类公民"。这意味着：

1. **身份与所有权**：每个 agent 有唯一的身份标识、角色定义和归属人，而不是一个匿名的 CLI 进程。
2. **统一执行契约**：同一个 agent 可以被调度到不同的运行时（Claude Code、Codex、Hermes 等），但身份、上下文、权限不变——通过 AgentRouter 实现运行时无关性。
3. **共享工作空间**：人类和 agent 在同一个空间中协作，文档、任务、输出有统一的存储，不再靠人工搬运上下文。
4. **权限与审批**：敏感操作走审批流，所有权限集中管理，可撤销、可审计。
5. **审计轨迹**：每个 agent 的每次操作、决策、产出都有完整记录，满足组织治理需求。

这和传统的"一个人在终端里调 agent"的根本区别在于：**agent 不再是你一个人的私有工具，而是整个团队可看见、可管理、可复用的数字员工。** 当组织里的 agent 数量从一两个增长到几十个时，没有这样的基础设施，效率瓶颈不在 agent 的能力上，而在人与 agent、agent 与 agent 之间的协调成本上。
