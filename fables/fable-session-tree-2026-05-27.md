# 分叉小径的制图师

古城地下有一座迷宫。传说它的入口藏在王宫花园一棵千年银杏树下，但从来没有人完整地走过它——不是因为太危险，而是因为每一个岔路口都会让你忘记自己是从哪里来的。

国王发布了一道诏令：谁能画出迷宫的完整地图，谁就是御用制图师，享一生荣华。

许多制图师来了。他们每人领到一卷空白的羊皮纸，一根炭笔，然后被送入迷宫。

第一个回来的制图师叫阿德里安。他画了一张非常清晰的路线图：从入口向南，遇到岔路向左，再向右，再向左，一路直达迷宫中央的宝藏室。"很简单，"他说，"只要每次都选左边的路。"

国王很高兴。但当第二位制图师薇拉回来时，她画的路线和阿德里安完全不同——她在第一个岔路口选了右边，然后走向了截然不同的方向。她也找到了宝藏室，但走的是另一条路。

"谁的地图是对的？"国王问。

"都对，"薇拉说，"但都不完整。"

国王不太满意。下一位制图师是个叫阿瑟的年轻人。他进了迷宫，走了三天三夜，出来时满身尘土，但只带回来一张奇怪的地图——上面画满了密密麻麻的符号和线条，看起来像一棵倒着长的树。

"这是什么？"国王皱眉。

"迷宫的真相，"阿瑟说。

他解释道：迷宫不是一条路，而是一棵树。入口是根。每一个岔路口都是一个分叉点。从同一个分叉点出发，向左走是一条枝，向右走是另一条枝。枝上还会继续分叉，越分越多。

"别的制图师把迷宫画成一条线——从起点到终点，中间每一笔都只记录他们选的那条路，"阿瑟说，"但我发现，如果你在第一个岔路口选了左边，走到一半发现死路，你不可能从地图上'擦掉'刚才走过的路，因为你已经走过了。路还在那里。你应该做的是回到那个岔路口，选右边，然后画一条新的枝。"

"所以我给每个岔路口都编了号。"他指着地图上一个标记，"这里是第七号岔路口。我第一次选了左边，走到了一面石墙。于是我回到七号，选了右边，这次走通了。但我没有擦掉左边那条死路——它还在地图上，只是旁边标了个记号，说明'此路不通'。"

国王若有所思。

"那你要怎么知道现在走在哪条路上？"大臣问。

"我总是追踪最外面的那片叶子，"阿瑟说，"你看这棵树，每条枝的末端就是一片叶子。我走过的路——最近走过的那条——它的末端叶子就是我现在所在的位置。不管我走到哪里，只要找到那片叶子，沿着枝一路倒回根部，就知道我完整的路径。"

大臣想挑毛病："那如果你在一个岔路口试了左边，发现走不通，回到岔路口选右边，走了很远，又发现需要回到更早的岔路口呢？"

"那我就回到更早的岔路口，从那里长出新的枝，"阿瑟平静地说，"旧的枝还在。我没有砍掉任何枝。那棵树只会越来越大，但永远记得所有的可能性。"

这番话让在场的一位老学者突然站了起来。他叫赫尔曼，是宫廷档案官，管理着王国所有的历史记录。

"你说旧枝不砍掉——但纸是有限的，"赫尔曼说，"如果这棵树无限生长，你的羊皮纸终究会画不下。"

阿瑟笑了。"所以我有一个秘密。"他从口袋里掏出一个小本子。"每次我回到一个岔路口，准备走新路之前，我都会从刚走过的那条旧路上提炼出一句话——'左边那条路走到第三间石室时，地上有一块松动的砖，下面藏着一把铜钥匙。'我把这句话写在新路的起点旁边。"

"这样即使我不回头走那条旧路，新路也知道旧路上发现了什么。"

"你的意思是……旧路的经验可以带给新路？"赫尔曼的眼睛亮了。

"对，"阿瑟说，"但不是把整条旧路搬过来——那太长了。我只提炼最关键的发现。就像……从一棵枝上摘一颗最甜的果子，带到另一棵枝上。"

国王沉默了很久。最后他站起来，走到阿瑟面前。

"你画的不是迷宫的地图，"他说，"你画的是**思考的形状**。"

他转向其他制图师："你们画的是走过的路。阿瑟画的是**所有可能的路**——包括走过的、走错的、还没走的、以及它们之间流动的经验。"

阿瑟被任命为御用制图师。多年后，他的方法成为制图学的基石。人们把它叫做**"分叉树记法"**。

而他那本小本子里记下的那些"旧路经验"，后来有了一个正式的名字：**分支摘要**。

---

💡 概念解析：会话树（Session Tree）

这则寓言讲的是 **Agent 会话树**——一种把 AI 对话存储为可分支的树结构而非线性数组的设计。

在大多数聊天系统中，对话就是一排消息：用户说一句，AI 回一句，像一条直线。但像 Pi Agent 这样的编码助手面临一个更复杂的需求：程序员在对话中会不断"试错"——让 AI 用方案 A 试试，不满意，回到刚才的节点换方案 B。传统的线性消息数组无法优雅地支持这种"回到过去，换一条路走"的探索模式。

会话树用三个核心字段解决这个问题：**id**（每条消息的唯一标识）、**parentId**（指向上一条消息，构成树的边）、**leafId**（当前活跃分支的最末端）。就像阿瑟给每个岔路口编号、追踪最外面的叶子一样——系统只要知道 leafId 在哪里，沿着 parentId 回溯到根，就能精确重建当前对话的完整上下文。

这些数据以 **JSONL** 格式（每行一个 JSON 对象）追加写入磁盘，而不是把整个对话序列化为一个大 JSON。这带来了崩溃恢复能力（进程崩溃时最后一行可能不完整，但前面的数据完好）和高效的长会话处理。

而"分支摘要"机制允许系统在切换到新分支时，把旧分支上发现的关键信息（比如"方案 A 发现了一个关键 bug"）带给新分支，避免重复踩坑。

这种设计特别适合**编码场景**——程序员天然需要探索多条路径，而好的工具不应该强迫他们在"继续走"和"回头试"之间二选一。
