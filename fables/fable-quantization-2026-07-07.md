# 量贩书店的精简术

在古老的数字王国里，有一位名叫阿涂的藏书家。他经营着一座庞大的图书馆，里面存放着八十亿张卡片，每张卡片上写着一个小数——0.0037、-0.8912、0.0016——精确到小数点后七位。

这些卡片有一个神奇的用途：把它们按特定顺序排列，放入"思维机器"中转动，机器就能回答任何问题。但卡片实在太多了。每张需要 32 个柜格来存放，整座图书馆占掉了 159 个巨大的仓库。别说普通学者了，就连国王自己的库存也快撑不住了。

"能不能小一点？"国王下令。

大臣甲出了个主意："把每个数字只保留一位小数吧。0.0037 变成 0.0，-0.8912 变成 -0.9。"

阿涂试了试。结果很糟糕。那些原本 0.0016、0.0023 的卡片全变成了 0.0。思维机器运转时，信号被 0.0 吞噬了——所有经过这些节点的路径都变成了零。机器像一个突然失忆的人，张着嘴却什么也说不出来。

大臣乙摇摇头说："太粗暴了。你把卡片都从 32 个柜格的格式直接扔进 4 个柜格的盒子里，当然不行。32 格的盒子能装从 -3 到 3 的数，可你的数字大多数都在 -1 到 0.2 之间，大部分空间都浪费了。"

他想出了一个聪明办法：**缩放**。先量出所有卡片里绝对值最大的那个数——-0.89——然后把整个范围"挤"进 -7 到 7 这十五个整数槽里。挤的时候除以一个比例因子，用的时候再乘回来。虽然 0.16 和 0.08 被挤到了同一个槽里（都变成了 1），解压后都是 0.1271，有些精度丢了，但好歹没有变成 0。

思维机器重新转了起来。回答变得有点模糊——像是人刚睡醒时说话，意思差不多，措辞偶尔跑偏。但至少它还能回答问题。最重要的是，仓库从 159 个缩小到了不到 40 个。

大臣丙皱眉道："还是不够好。你们看看这些数字——最小值是 -0.89，最大值才 0.16。你们的方法里正数方向撑到了 0.89，可最大的正数只有 0.16。正数那边一半的空间全浪费了。"

他提出了一个**不对称**的方案：不用 0 当对称中心，而是让 -0.89 映射到 -8，0.16 映射到 7。用一个偏移量（zero point）来记住 0 落在哪里。用的时候，先减去偏移量，再乘以比例。就这样，同样的 4 位存储空间，精度误差从 18% 降到了 8.5%。

但最棘手的问题来了。

阿涂在整理卡片时，发现了一张奇怪的卡片，上面写着 **10.0**。其余八十亿张都在 -1 到 1 之间，偏偏这一张是个异类。

如果按常规方法缩放，那 10.0 会把整个比例因子拉到巨大的数字——大部分卡片挤在一起，精度全部丧失。就像一个教室里坐着 99 个小学生和 1 个巨人，桌椅必须按巨人的尺寸来配，结果所有小学生连脚都够不着地。

阿涂的最终方案是：**分块**。把八十亿张卡片分成每组 64 张的小组，每组独立计算自己的比例因子和偏移量。那张 10.0 的卡片被和它附近的同类分在一组，不会再祸害其他组。精度损失被控制在局部，整体机器的输出几乎和原来一样好。

国王看了实验结果：缩小到四分之一大小，精度只损失 5% 到 10%，而且因为卡片少了，搬动起来更快——思维机器的推理速度反而翻了一倍。

大臣甲喃喃道："我以为缩小就意味着变差。没想到……精度损失不是线性的。从 32 格缩到 16 格，几乎无损。从 16 格缩到 8 格，也几乎没有变化。从 16 格缩到 4 格，损失明显但不致命。真正崩塌的是缩到 2 格——那才是悬崖。"

阿涂在日记里写道：

> 大多数数字都挤在 0 附近，这是思维的规律。只要缩放得当，精度就不是瓶颈——空间才是。

## 💡 概念解析：量化（Quantization）

量化是大语言模型压缩的核心技术。LLM 的参数（权重）默认以浮点数存储——通常是 16 位（bfloat16 或 float16），每个参数占 2 字节。一个 80B 参数的模型需要约 160GB 内存。

量化的原理是**有损压缩**：将浮点数映射到位数更低的整数空间。从 16 位压缩到 4 位，模型体积缩小为原来的 1/4。关键在于不能简单地"四舍五入"——原始浮点格式（如 float4）的固定范围（-3 到 3）和参数的实际分布（集中在 0 附近）不匹配，会导致大量参数被截断为 0，模型彻底崩溃。

实践中使用的方法是**分组缩放**：每 32-256 个参数为一组，找到该组的最大值和最小值，计算一个比例因子（scale）和偏移量（zero point），将浮点值映射到整数范围。推理时再通过"乘以 scale 加上 zero"反量化。对称量化以 0 为中心，非对称量化允许零点偏移，能更好地利用有限的整数槽位。

量化的效果出人意料地好：16 位到 8 位几乎无损，到 4 位通常只损失 5-10% 的精度。这是因为模型参数天然集中在 0 附近（训练过程中正则化的效果），而低精度浮点恰恰在小值附近有最高的表示密度。真正的"质量悬崖"通常出现在 2 位以下。此外，量化后的模型不仅占用内存更少，推理速度反而更快——因为 GPU 内存带宽是主要瓶颈，更少的数据搬运意味着更高的吞吐量。
