📖 每日工程寓言 — Subagent 身份化与怀疑论者验证

# 怀疑者的眼睛

大梁朝刑部接到一桩让所有人头疼的案子。

江南盐运使府的账册、书信、契约堆了三间屋子，涉及十七个县的官员、四十多家商号、整整三年的盐引流转。刑部郎中张大人看了三天三夜，眼睛熬得通红，也只理出个大概轮廓。

他把案卷推给手下最得力的推官老周："这案子你全权审理。"

老周是刑部公认的全才，刑律熟、账目通、勘验经验丰富。他接下案子，埋头苦干了十天。

十天之后，老周交上一份洋洋洒洒两万字的报告。张大人越看越皱眉头——第三页说账目对不上，第十三页又说账目没问题；第七页有个证人说他当时在苏州，第十七页又引用同一人在杭州的证词。两万字里自相矛盾的地方不下十几处。

张大人把老周叫来："你这是怎么回事？"

老周一脸委屈："大人，这件案子涉及面太广了。账、证、物、人，每一样我都是亲自查的，但兼顾不过来，难免有疏漏。"

张大人刚要发作，一旁一直沉默的主簿王大人开口了：

"大人，老周的问题不在于不认真，在于他想一个人做所有人的事。不如将案子拆成几块，让各有所长的同僚分头去查。"

"分头去查？"张大人问，"那最后谁来做结论？"

"做结论的人，应该不参与调查。调查的人，也不该知道别人的结论。"

张大人觉得这个说法很奇怪，但又挑不出毛病。他同意了。

王主簿从刑部调了四位推官，每人只负责一件事。

**第一位，账目推官蔡大人。** 他只拿到一屋子账册，其他什么都不看。蔡大人在书房里关了五天，出来后写了一份纯账目报告："盐引账目有二十三处缺口，约八万两白银。但有些账是故意做平的，手法很专业，不是外行人干的。我只看账，不知道这是谁干的。"

**第二位，物证推官钱大人。** 他接管了书信和契约。把每份文书拓印、比对笔迹、检验墨迹年份。三天后上报："盐引中有十三份是事后补签的，墨迹水分未干透。其中五份是同一人笔迹假扮了三个不同的人名。我只看物证，不确认这些人在案子里的角色。"

**第三位，人证推官孙大人。** 他出京跑了半个月，把所有关键证人审了一遍。回来时交了一份只有事实的名单——每个人说了什么、有什么互证关系。他不做判断，只记录。

**第四位，现场推官李大人。** 他实地测绘了盐运使府的仓库、码头、账房位置。发现账册里反复提到的"三号仓库"在现实中根本不存在——图纸上有，但地上一片空地。他画了一张实测对比图，把矛盾标得清清楚楚。

四位推官各交了一份报告。每人只知道自己的那块拼图。

这时候，王主簿请出一个人——老钱。

老钱是刑部退休的老推官，干了四十年，以"不相信任何人"闻名。年轻人说他脾气臭，鸡蛋里挑骨头。张大人一直不太喜欢他。王主簿却把四份报告锁在一个匣子里交给老钱：

"你看一遍。只找矛盾、存疑、互斥的地方。你只负责质疑，不负责解答。"

老钱接过匣子，关了三天门。出来时，四份报告上贴满了密密麻麻的批注。

他指着账目报告和人证报告说——

"蔡大人说银两缺口八万两。孙大人的证人交代说涉案官员私下分了'十几万两'。差了四万两——要么账没查全，要么证人在撒谎。这两个结论不可能都对。"

又指着物证报告和勘验报告说——

"李大人说三号仓库不存在。但钱大人从三号仓库寄出的信里提取了三份笔迹样本。要么信是伪造的，要么这座仓库存在过但被拆了。反正有一个前提是错的。"

再翻到人证报告：

"孙大人的口供里有个关键证人说自己案发时在外地。但钱大人的笔迹鉴定显示，同一时间有一份以他名义签署的文件在这里。这个人要么会分身术，要么被顶替了。"

张大人听完，后背出了一层冷汗。

如果按老周之前的做法，这些矛盾全被埋在两万字里，没人会发现。但经过四位专审官各自隔离勘验、再由老钱交叉验证之后，真相像拼图一样自己浮现出来——哪里有漏洞，哪里需要复查，哪里可以定案，一目了然。

张大人在最终的结案报告上盖了印，然后问老钱：

"你只看了三天，怎么比我手下干了半个月的人看得还准？"

老钱收起匣子，淡淡地说：

"因为他们都在找答案。我不用——我的工作就是证明他们找的答案是错的。当你不需要爱上自己的结论时，眼睛就亮了。"


💡 概念解析：Subagent 身份化 + 怀疑论者交叉验证

这个故事讲的是 **Subagent 身份化实践**——在动态工作流（Dynamic Workflows）中，给每个子 Agent 分配一个专业性极强的身份和明确的职责边界，而非使用通用身份。这是 Claude Code 动态工作流的高级用法，由超级个体｜柿子（@yaohui12138）在 2026 年 6 月系统阐述。

核心机制有三层：

1. **专业化身份隔离** — 每个 Subagent 通过 `/agents` 创建时，拥有针对性的系统提示词、受限制的工具权限（如只读代码、禁止修改）和固定的输出格式。像故事中每人只查一类证据，杜绝"全才试图做所有事"的分散。

2. **隔离上下文窗口** — 每个 Subagent 在独立的上下文窗口中工作，结果先写入脚本变量，不污染主 Agent 的上下文。只有线程聚合时才会汇总——这与故事中四份报告各自密封、互不知情完全一致。

3. **怀疑论者 Agent 对抗验证** — 在所有专业化 Subagent 完成后，启动一个专门的**对立验证 Agent**（Adversarial Verification），它的任务不是寻找正确答案，而是逐一质疑每个 Subagent 的发现，找出内部矛盾和不一致。老钱就是它的化身——"不负责找答案，只负责证明别人的答案是错的"。

这套实践的核心价值在于：大多数人停留在"AI 能写代码"的认知层。真正的效率跃升在于像架构师一样把复杂任务拆解成可并行的子任务，用专业化 Agent 团队执行，再用对抗验证消除单一 Agent 的自我偏好偏差（self-preferential bias）。从"一个人做所有事"到"一支专业团队并行作战"，是从工具使用到系统设计的认知跨越。
