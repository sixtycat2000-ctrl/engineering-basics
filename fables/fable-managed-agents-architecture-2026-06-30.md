# 三位一体解耦

铁城里最了不起的人叫阿特拉斯。

他一个人干三个人的活：**记住**所有工程的历史（从哪年哪月修的哪座桥，用了多少石料，谁提过什么建议），**思考**每个新项目的方案（该怎么修，该派谁去，先做什么后做什么），还要**亲手**砌砖刷墙。

铁城人叫他"万能匠人"，但他自己知道，他更像是头**驮兽**——背上绑着三样东西，哪样都卸不下来。

---

阿特拉斯有个习惯，让人又敬又怕。

他不写任何东西下来。

"都在我脑子里。"他总这么说。确实，他的记忆力惊人——三十年前的地基图他都能背出来。但这也意味着，**如果他倒下，所有记忆就跟着消失了**。铁城没有第二个人知道城墙裂缝的确切位置，也没有人知道上次大修时为什么放弃了原来的方案。

城主提过好几次："阿特拉斯，你能不能把你知道的东西写下来？"

他摆摆手："浪费时间。问我就行。"

更糟糕的是安全问题。阿特拉斯掌管着铁城的金库钥匙、城墙警报密码、矿脉通行证——全都揣在自己口袋里。有一次，一个新来的学徒偷偷翻他的工具包，差点就拿到了金库钥匙。城主知道后急出一身冷汗，但阿特拉斯只是皱了皱眉："以后看好就行。"

大家都觉得这没问题——直到大旱来了。

---

那年夏天，铁城需要同时修三条引水渠。东渠给农田供水，西渠给冶炼炉送水，北渠是城里的饮用水源。三条渠同时断水，等不得。

阿特拉斯去了东渠。他站在工地，记忆告诉他去年的地基还在，判断说要先清淤再砌石，然后撸起袖子开始搬石头。

三天后，他听到西渠的工程师在抱怨：不知道西渠去年修缮时换了哪种石料，不敢随便加固。阿特拉斯拍拍脑袋——他当然记得，但他在东渠，脱不开身。

第五天，北渠那边传来消息：饮用水源检测出杂质，需要立刻改道。城主急了，派人去找阿特拉斯。

阿特拉斯放下手中的石头，深吸一口气，看着三条还没修完的渠，第一次感到了无力。

"我是万能匠人，"他喃喃自语，"但我只有一双手。"

---

转折发生在一个叫伊萨的年轻顾问到来之后。

伊萨是邻国来的，见过他们的工程体系。她站在城墙上，看了一周，然后对城主说了一句让所有人震惊的话：

"你们的问题不是阿特拉斯不够强，而是**你们把三样东西绑在了一个人身上**。"

她摊开一张图纸，画了三个圆：

"第一样是**记忆**——所有工程的来龙去脉，谁做了什么决策，结果怎样。这不是一个人该扛在脑子里的东西，它应该被**写下来**，永远不删除，任何人随时能查。

"第二样是**思考**——接到一个新任务，先查记忆，再判断该怎么做，然后把指令发出去。思考的人不需要自己动手，他只需要知道该让谁做什么。

"第三样是**动手**——收到指令就干活，干完了报告结果。干活的人不需要记住历史，也不需要做大决策，他只需要照着办。"

城主皱眉："这不就是把阿特拉斯拆成三个人吗？那有什么好处？"

伊萨竖起一根手指："**好处是：任何一个死了，其他两个都还在。**"

---

铁城花了半年时间重建体系。

**档案官**设立了一个巨大的石碑群，每发生一件事就刻上去，永远不擦除。所有的工程记录、决策理由、测量数据，全在碑上。任何人都可以来查，但没人能改。

**工头**们坐在指挥部里，不看工地，只看石碑和报告。接到新任务时，他们先去查碑上的历史记录，再判断方案，最后把指令写成纸条发给工坊。

**工坊**是流水线式的。一组泥瓦匠收到纸条就开始干活——不管是谁写的纸条，不管之前发生了什么，他们只管把这块墙砌好，然后写一张回执："第三段地基完成，用石料二百四十块。"

一开始乱成一团。工头们抱怨："以前我站在工地上就知道砖砌歪了没有，现在只能看回执！"

泥瓦匠也抱怨："以前阿特拉斯一边砌砖一边改方案，现在纸条来了才发现方案已经过时了！"

但伊萨说："**乱是暂时的，脆弱才是永久的。**"

---

三个月后，事情起了变化。

东渠工坊的一场暴雨冲塌了脚手架。搁在旧体系里，这至少要停工五天——等阿特拉斯回忆起工程进度、重新评估方案、再亲自去修。

但现在：泥瓦匠写了一张回执："脚手架塌了，第十七段未完成。"档案官把这条刻在碑上。新上任的工头看了看碑上记录——啊，第十七段是去年换过地基的薄弱段。他写了一张新纸条："先加固十六段，再重建十七段脚手架。"新的泥瓦匠组接手，三天后工坊恢复运转。

**工坊死了，但记忆没丢，决策没断，新的手接上来继续干。**

更大的惊喜发生在旱季快结束的时候。城主发现，可以同时派**三个工头**去指挥三条渠——档案官只有一组石碑，三个工头可以同时来查。十组工坊可以同时开工。

"以前只有一个阿特拉斯，"城主喃喃道，"现在等于同时有了三个。"

伊萨笑着纠正："不是三个阿特拉斯。是**一套体系**，可以变成三个，也可以变成三十个。"

她拍了拍石碑："因为这里的记忆，不会因为人多而变少。"

---

阿特拉斯起初很失落。

他被从"万能匠人"的宝座上请了下来——他不再一个人扛三样东西了。但渐渐地，他发现自己反而更自由了。他的判断力依然无人能及，现在他可以专心做**工头**——研究方案、调度资源——而不必亲自搬石头。

有一天晚上，他站在东渠旁，看着流水穿过新建的渠壁。他想起那个大旱的夏天，想起自己的无力感。

"以前我是个**宠物**，"他对伊萨说，"独一无二，不可替代——但也一碰就碎。"

"现在呢？"

"现在我们是**牲口**，"他笑着说，"随时可以换一批，但怎么也杀不完。"

伊萨没纠正他用词，但她心里知道：他说的"牲口"，其实是这个词在工程师世界里的最高评价——**cattle-grade**。

💡 **概念解析：Managed Agents 架构 — Session / Harness / Sandbox 解耦**

Anthropic 的 Managed Agents 服务将 AI Agent 拆成三个独立组件：

**Session（会话）**是一个只追加（append-only）的事件日志，记录 Agent 运行过程中发生的所有事情。它持久化存储在上下文窗口之外，可以随时查询——回溯某个时刻的决策、从中断处恢复、重新读取特定时间段的上下文。Session 解决的核心问题是：长任务超出上下文窗口时，如何不丢失信息。

**Harness（线束）**是无状态的编排循环——它调用大模型做决策，并将工具调用路由到正确的执行环境。Harness 本身不存储任何状态，所以它可以随时被替换：一个 Harness 崩溃了，新的 Harness 从 Session 日志恢复，无缝接管。

**Sandbox（沙箱）**是执行环境——Agent 在里面运行代码、编辑文件。Sandbox 对 Harness 来说只是一个工具：`execute(name, input) → string`。Sandbox 可能是容器、手机模拟器、甚至游戏机——Harness 不关心。Sandbox 挂了？Harness 把错误传给模型，模型决定是重试还是换策略，然后提供新环境。

这三层解耦的核心收益：**任何一层失败都不影响其他两层**。Sandbox 崩溃不丢上下文（Session 还在），Harness 崩溃不丢进度（从 Session 恢复），Session 独立存储意味着可以按需组织上下文（Harness 的策略可以随模型升级而改变）。这就像把传统上绑在一个容器里的"宠物"拆成了可以独立扩缩容的"牲口"——p50 延迟下降 60%，p95 延迟下降 90%。
