# 📖 每日工程寓言 — 共享设计语言

在一座远近闻名的造城王国里，有三个匠人行会——画师会、石匠会和漆匠会。每个行会都有自己的黑话，外人听来如同天书。

画师会说"这块需要一点呼吸感"，石匠会说"接缝要对齐网格"，漆匠会说"色调再退一点"。三百年了，他们之间只靠比划和写意来沟通。偶尔运气好，造出来的东西能看；多数时候，钟楼歪了，墙壁色差肉眼可见，门把手上没有留出足够的位置给手指。

王国最年轻的工部尚书叫殷简，接到了一个棘手的差事：国王要盖一座前所未有的图书馆，同时动用三个行会的匠人。

殷简第一天就遇到了麻烦。

"大厅的主色要庄严但不沉重，"国王说。

殷简把这话转给画师。画师理解为"深色调低饱和"，给了一整套暗色方案。殷简转给石匠，石匠理解为"用深色大理石"，采购了整整三船黑曜石。殷简转给漆匠，漆匠理解为"在暗色表面加一点温暖"，调出了琥珀色。

三路人马各自完工，拼到一起：黑曜石墙面配上琥珀色漆面，暗色背景上的装饰金线在阴影中完全看不见，而大厅的采光因为所有表面都吸光，白天也需要点灯。

国王站在大厅中央，沉默了很久，说："这不是我要的。"

殷简试过另一种方式——更详细的描述。他给画师写了"柱子之间的间距要刚好能让两个人并肩走过不碰肩"。结果柱子间距变成了 1.8 米——恰好是殷简自己的肩宽加一点余量，但国王的侍卫（肩宽 1.6 米）走过去绰绰有余，而国王本人（体态宽厚）需要侧身。

"你说的'刚好'是多刚好？"画师委屈地说。

殷简意识到，问题不在态度，不在技术，甚至不在那一船黑曜石。问题在于：**他们没有一个共享的词汇表。**

每一句"让它好看一点""间距合适就行""颜色再调调"——这些话在三个行会的耳朵里，映射到了完全不同的操作。不是他们不想协作，而是**语言本身没有给协作留下接口**。

于是殷简做了一件前无古人的事。

他花了半年，把三个行会的黑话全部翻译成一份《共用语典》。不是字典，不是教科书——而是一份**操作手册**，每个词条都有精确的数值、行为定义和使用场景。

比如"呼吸感"这个词，被拆成了：
- 间距不小于 8 个长度单位（约成年人一掌宽）
- 同组元素之间的留白应大于组与组之间的留白
- 负空间面积至少占整体面积的 20%

"庄严但不沉重"被重新定义为：
- 主色调亮度值不低于 70%（避免吸光）
- 暖色偏移不超过色相环 15 度（保持庄重感）
- 表面纹理使用哑光而非镜面（降低压迫感）

"退一点"被精确为：
- 饱和度降低 25%，而非亮度降低 25%
- 因为降亮度会让颜色变灰，而降饱和度能让颜色保持活力但更柔和

——最后一条让殷简自己吃了一惊。他过去一直以为"退"就是"变淡"，但在漆匠的语言里，"变淡"和"变柔"是完全不同的操作。

语典完成后，殷简做了一次实验。他把图书馆的大厅拆掉重来，这次只用语典里的词条下达指令。

结果令所有人意外：三个行会第一次不需要反复确认就能开工，因为每个词都指向唯一的行为。石匠看到"柱间距 2.4 米"不会再问"是内径还是外径"，因为语典里写明了"间距指柱面到柱面的净距离"。画师看到"亮度值 75%"不会再去猜是 RGB 空间还是感知亮度，因为语典里指定了使用 OKLCH 空间——一种与人类视觉感知对齐的色彩模型。

图书馆落成那天，国王在大厅里走了很久。

"感觉如何？"殷简问。

"说不上来哪里好，"国王说，"但每个角落都让人觉得……正合适。"

殷简笑了。他知道秘密不在天赋，不在灵感，而在那本不起眼的语典：**当所有人都用同一套精确的词汇描述意图时，理解就不再是概率，而是确定性。**

## 💡 概念解析：共享设计语言（Shared Design Vocabulary）

这则寓言讲的是 **共享领域词汇表（Shared Domain Vocabulary）**——一个被严重低估的工程基础设施。

在软件和设计领域，"让它好看一点""间距合适就行""颜色再调调"这类模糊指令每天都在发生。设计师用一套术语，开发者用另一套，AI Agent 用第三套。看似在沟通，实际上每个人都在用自己的词典解码同样的句子，映射到完全不同的操作。

**Index.how 的设计词汇表（188 个术语）** 正是这种"语典"的一个现代实例。它做了一件关键的事：**把设计师的直觉词汇翻译成可执行的行为定义。**

- "Weight"不只是"粗细"——它区分了粗体（UI 层级强调）和斜体（语言学强调），两个操作在工程中实现方式完全不同
- "Popover"和"Tooltip"不只是"弹出的小东西"——前者可以包含交互内容（按钮、链接），后者不能，这个区分直接决定了用哪个 HTML 组件
- "Chroma 降 25%"和"Opacity 降 25%"——前者保持颜色活力只降低饱和度，后者让颜色变灰（完全不同的视觉效果）

这背后有一个更通用的工程原则：**当一个领域的协作方超过两方时，自然语言的模糊性会成为系统性的错误源。** 共享词汇表的本质是一份**接口契约**——它把自然语言变成了一种精确的协议，让设计师、开发者和 AI Agent 能够无歧义地传递设计意图。

这和 API 接口文档、类型系统、Schema 定义是同一种东西——只不过作用域从代码扩展到了视觉设计。当你的团队（包括 AI Agent）掌握了这 188 个术语，"让它好看一点"就能变成"增大标签的 tracking，使用 tinted neutral 作为边框，用 clamp 实现流式字号"——每一条都指向确定的行为，不再需要猜。

**共享词汇的投入回报比极高：编写一次，消除无数次沟通歧义。它不是文档，是协议。**
