📖 每日工程寓言 — 模糊目标结构化元技能

# 槐树镇的传话人

槐树镇最让匠人头疼的，不是材料稀缺，也不是工具老旧，而是镇长老陈。

老陈是个好镇长，但他下订单的方式能把最好的工匠逼疯。他找到铁匠铺的王师傅，说：“打一把好锄头。”

王师傅问：“多长？多宽？什么钢？”

老陈摆手：“你看着办，打一把好的就行。”

三天后，王师傅捧出一把沉甸甸的花纹钢锄头，柄是檀木的，刃口开了镜面。老陈拿起来看了看，说：“太沉了，不方便。”

王师傅又打了三天，换成轻竹柄、薄刃口。老陈又说：“太轻了，一碰石头就卷刃。”

王师傅改到第五版时，整个人坐在风箱前发呆。他不是不会打锄头——他打了三十年——但他不知道“好”是什么意思。老陈嘴里的“好”像一团雾，伸手抓不着。

木匠老周、瓦匠老李、皮匠小刘，全都经历过同样的事。镇上传开了：老陈的活，没法接。可是不接吧，全镇最大的雇主就是他。

事情在秋天起了变化。

镇上来了一位外乡人，姓乔，长得瘦瘦的，戴一副圆眼镜，不爱说话。他每天坐在茶馆角落，拿一支笔在小本子上写写画画。有人问他来做什么，他说：“我帮人传话。”

谁也不信。传话算什么本事？

直到有一天，老陈又来找王师傅。王师傅正要推辞，乔先生出现了。

“您想打一把锄头？”他问老陈。

老陈点头。

乔先生从兜里掏出一张纸，上面画着格子。“我问几个问题，您答就行。”

“第一，这把锄头用在沙地还是黏土地？”
“沙地。”
“第二，每天用多久？”
“也就一个时辰，腰不好。”
“第三，以前用的锄头哪里不满意？”
“太重了，挥几下就喘。”
“第四，您说的‘好’，是什么感觉？”
老陈想了想：“三个月内不用磨，柄握上去不硌手。”

乔先生低头写了几笔，翻到第二页：“还有什么绝对不能有的？”
“不能用红木柄，我对红木粉过敏。”
“做坏了怎么办？”
“那就重做呗，又不是不认账。”
“如果三天做不出来呢？”
“那就算了，不急着用。”

乔先生合上本子，转向王师傅，递过去一张纸。纸上写得清清楚楚：

> **目标：沙地轻便锄头**
> - 材料：普通碳钢，不必花纹钢
> - 柄材：白蜡杆，禁用红木
> - 重量：不超过 2 斤
> - 刃口：30 天内不重磨
> - 工期：3 天
> - 验收标准：单手挥 20 下不喘息
> - 失败预案：第 3 天未完成即停工，无需赔偿

王师傅看了一眼，心里全亮了。五天？不用。两个时辰他就干完了。

锄头交到老陈手上那天，老陈试了试，笑了。他看看乔先生，又看看王师傅，说：“你怎么知道我要的是这个？”

乔先生推了推眼镜：“您其实一直都知道自己想要什么。只是您说的和需要的，中间隔了一层。”

消息传开之后，全镇的匠人都来找乔先生传话。老周的木料订单、老李的瓦片规格、小刘的马鞍尺寸——乔先生每次都掏出一张格子纸，问上四五个问题，然后给出一份谁看了都明白的说明。

渐渐地，有人发现乔先生的传话不是乱问的。他那张纸上的格子，永远是那几栏：目标、约束、边界、验收标准、失败预案。他有一套死规矩——听到“高级”就问“和什么比”；听到“有质感”就问“摸上去什么感觉”；听到“差不多就行”就直接划掉，非要对方说清楚，差到什么程度能接受。

还有一条规矩更绝：如果对方说“你先试试，不行再改”，乔先生就会停下笔，说：“你想好一次再找我。我不能让别人白做。”

镇上的人开始私下议论：“乔先生这是把话翻成了图纸啊。”

老陈后来问他：“你这个传话的法子，有名字吗？”

乔先生说：“这哪算什么名字。不过是把一团雾，变成一张单子罢了。”


💡 概念解析：模糊目标结构化元技能（Goal Meta-Skill）

qiaomu-goal-meta-skill 是 Codex /goal 系统的一个元技能——它不直接执行任务，而是将人类的模糊意图翻译成 agent 可精确执行的格式化目标。

核心洞察是：**大多数 agent 任务失败不是因为模型不会写代码，而是目标太松散。** 当人说“做个 App”或“改好看点”时，缺少四大要素：

1. **Verification（验收标准）** — 怎么确认做对了？需要将“有质感”“像官网”这类模糊词翻译成可测量的检查项
2. **Boundaries（边界约束）** — 什么不该碰？禁用材料、不可修改的模块、性能底线
3. **Iteration Policy（迭代策略）** — 失败后怎么处理？重试次数、回退方案、何时换方案
4. **Pause Conditions（暂停条件）** — 什么时候必须停下来？超时、成本超限、触及敏感领域

这个模式的关键设计原则包括：**Default to Progress**（低风险不确定性直接做合理假设，不让用户卡在表单里）、**Pause Only for High-Risk**（只在涉及版权/支付/生产部署时强制暂停）、以及**模糊词编译器**（将“高级”“专业”“美观”这类词编译成具体的验证步骤）。

本质上，这是一个位于人类意图和 agent 执行之间的**翻译层**——就像高级语言编译器把人类可读的代码翻译成机器可执行的指令。它的价值不在于写更好的 prompt，而在于建立了一个结构化的转换协议，让非专业用户也能输出 agent 能执行的精确目标。
