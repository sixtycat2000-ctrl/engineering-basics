# 渔村的两位大师

东海岸有个小渔村，名叫浪花湾。村里有两个人最受尊敬。

一个是老渔夫海伯。今年六十三，打了四十年鱼。他往码头上一站，看看天色，闻闻风里的盐味，听听海鸥叫的方向，就知道鱼群在哪里。那年腊月，所有人说冬天没鱼，海伯却带船出了海。三个小时后回来，满舱大黄鱼。村长问他怎么知道的，他挠挠头："水面反光的方式不对，有东西在底下。"

没人能从他嘴里问出一个公式。

另一个是航算师阿明。才二十八，是村里唯一去过城里读书的年轻人。他带着一把尺子、一个精密罗盘、一本自己手抄的潮汐表。出海的时候，他能精确算出船要在几点十三分出发、以一百一十七度的角度切入洋流、耗四十二升燃油、下午四点五十七分返回。他经手的航线，从未偏过半里。

村里人私底下说：海伯知道鱼在哪里，阿明知道怎么把船开到那里。两个人各司其职，浪花湾成了东海岸最富裕的小村。

转折发生在那年冬天。一场罕见的暴风雨冲毁了码头。村长召集全村："必须在开春前修好码头，否则明年一整季出不了海。这关系到全村人的饭碗。"

海伯拍着胸脯请缨："规划的事交给我。"

他站在废墟前，闭上眼睛，感受海风的方向，观察浪花拍岸的纹路，然后指着东面的浅滩说："木材从那里下水，沿着礁石外侧拉过来。"

六个壮汉按他说的干了三天。木材确实运到了——但比预计晚了整整一天。原因是他"感觉"的潮水方向恰好反了，浅滩通道退潮后水深不到半尺，满载的木排直接搁浅。六个人在冰冷的海水里推了六个小时。

海伯脸上有点挂不住："潮水变了。我重新判断一下。"

第二次，他换了方向。这次倒是顺利运到了，但数量出了问题。他"觉得"三根主梁就够了，村里老木匠摇摇头说至少七根。海伯坚持自己的判断。结果第一根梁刚架上去，就明显撑不住——间距太大，中间塌了下去。

阿明一直在旁边看着，眉头越皱越紧。第三根梁断裂那天，他终于忍不住了："海伯哥，算梁的间距、承重和潮汐时间——这种事，能不能让我来算？"

海伯不高兴了："我打了一辈子鱼，修了三回码头，凭经验就够了。你那个什么表，能感觉到浪往哪走吗？"

阿明沉默了。

第二天，村长来找阿明："木材到位了，码头的结构设计你来负责吧。"

阿明点头，拿出纸笔。他量了每一根木材的精确尺寸，用三角函数算了承重、力矩、应力分布，画了一张极其精确的结构图。

但画完之后，他自己看着也觉得别扭。码头的位置和角度在力学上是最优的，可那个方向——正好是冬天西北风灌进来的口子。站在上面钓鱼会被吹得站不稳。而且那个角度，早上的日出刚好被灯塔挡住——那是浪花湾渔民一天中最享受的时刻。

他改了三次。每次数据上更精确了，但看着更不像"浪花湾的码头"。像一个铁盒子硬插在海岸线上，跟整个湾的弧度格格不入。

他拿着图纸去找海伯："你帮我看看这个方向行不行。"

海伯看了一眼，没看数字，而是走到海边站了一会儿。回来指着图纸上另一个位置："从这里伸出去，顺着湾的弧度，避开风口。日出刚好从两块礁石中间升起来。"

阿明按海伯指的位置重新算了一遍——力学上不是最优的，但也足够安全。他补了几个加固点，数据全部对齐。

码头修好的那天，全村人在上面吃庆功宴。村长站起来说了一番话："海伯知道鱼在哪里，阿明知道怎么把船开到那里。修码头的时候也一样——海伯知道该往哪修，阿明知道怎么修得稳。你们谁也别干对方的活。"

海伯端着酒碗看着阿明，笑了："小子，下次出海，航线还是你来定。"

阿明也笑了："鱼在哪里，还是您说了算。"

💡 概念解析：Latent vs Deterministic（隐空间判断与确定性计算）

这是 AI Agent 设计中"最有影响力的区分"（the most consequential distinction in agent design），由 Garry Tan 在分析 Claude Code 架构时明确提出。

**隐空间（Latent）** 指的是大语言模型的推理能力——判断、综合、模式识别。海伯"感觉到"鱼在哪里，靠的不是公式，而是四十年积累的直觉。同样，当模型判断一段代码"设计上不太对"、从模糊需求中提炼方案、或者从六千份资料中找到最相关的三份——这些都是"感觉"的领域。无法公式化，但准确得出奇。

**确定性（Deterministic）** 指的是工具和脚本的精确执行——计算、查询、排序、格式转换。阿明的罗盘和潮汐表，精确到分钟和角度。SQL 查询、算术运算、文件系统操作——这些有明确正确答案的任务，就是确定性领域。完全可复现，不会因为"今天状态不好"而算错。

**核心错误：把确定性任务交给模型去做。** 海伯"觉得"三根梁够，实际上差了一倍多。结果看起来完全合理——他是一个德高望重的大师，怎么会错？但他就是错了。让模型计算"847 条记录中哪些满足 17 条交叉筛选条件"，它可能给出一个"看起来完全正确"的结果，实际漏了 3 条、多了 2 条。确定性任务必须用确定性工具——脚本、SQL、正则表达式。模型负责那些"没有标准答案"的判断。

反过来也一样。让阿明凭公式决定码头修在哪里，力学最优但站着冻死人。规则系统可以精确匹配关键词，但无法理解"这段话的真正意图是什么"。

最好的 Agent 系统，是海伯和阿明各干各的：模型负责判断和综合，工具负责精确执行。两者之间的边界，需要设计者"冷酷地"划分——Forcing a deterministic problem through a model produces outputs that look plausible and are wrong（把确定性问题塞进模型，产出的结果看起来合理，但就是错的）。
