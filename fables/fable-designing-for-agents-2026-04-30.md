# 每日工程寓言 — 为 Agent 设计产品

## 标签纸

在古老的梅里迪安城，有一座大集市。

几百年来，规矩很简单：买主亲自走进摊位，翻看货物，和商人讨价还价，把东西抱回家。集市是为**人**设计的——宽阔的过道、彩色的招牌、热情的商人。

后来，变化悄然发生。

城里最有钱的公民开始派**管家**替他们跑腿。起初商人们没当回事，管家用什么就买什么，跟普通顾客没什么两样。

但问题很快暴露出来。管家不像他们的主人，没有那些积累多年的直觉。他们不知道"这块布摸起来像丝绸但不是"，也分不清"这味香料两个月后会走味"。

大多数商人的反应是耸耸肩："管家不懂？让他回去问他主人去。"

但集市东头卖文具的诺拉不这么想。她注意到，来替主人买纸的管家总是选错克重——他们拿走普通信纸，却不知道主人要写的是书法，需要 120 克的冷压棉纸。

诺拉没有责怪管家。她在每一摞纸的架子上贴了一张小标签：

> "如果你的主人练书法，需要 120 克冷压棉纸。不要猜——翻过来读背面说明。"

管家们开始读标签。订单变准了。

隔壁卖墨水的商人嘲笑她："你在替管家干活！"

诺拉笑了笑："我没有替他们干活。我是在**教他们怎么在我的店里成功**。管家的目标跟买主的目标一样——买对东西。我为什么要设置障碍？"

---

一年后，趋势加速了。不只是富人，**几乎所有人**都在派管家。集市的人流量在一夜之间从八成亲自购物变成了八成管家代购。

大多数商人还守着彩色招牌和热情微笑——设计给那些已经不再亲自来的人看的。少数有远见的商人，开始做更深的改变。

香料商在柜台放了一个**意见箱**。管家可以留一张纸条："主人要四川花椒，但我分不清哪个罐子是。标签上的字我看不懂。"

香料商读这些纸条。他开始用多种文字贴标签，还在每个罐子上加了刮刮闻的试香纸。每一条反馈都让他的店铺对管家更友好。

几个月后，他注意到反馈里反复出现一种说法："主人让我配腌料，但我不知道哪些香料该放在一起。"

于是他做了**腌料套装**——预先搭配好的香料组合，标签清晰。他不需要去问顾客想要什么。顾客的**管家通过困惑和反馈，已经在告诉他下一个该造什么产品了**。

---

但最深刻的改变，来自最不可能的人——城里的**税务官**，老陈。

几十年来，税表有 150 个字段。市民来到他的衙门，盯着表格问："这笔填哪个格子？"老陈指一下，市民填好，皆大欢喜。

管家开始代办税务之后，一切都崩了。管家盯着 150 个格子，完全不知道哪些跟自己的主人有关。要么全填（全是错），要么全空（等着被退回）。

老陈起初写了一本指南。"先读这 40 页手册再填。"管家没人读。

然后他顿悟了。问题不是管家笨，而是**两边各知道一些对方不知道的事**。

管家知道：主人做什么营生、跟谁做生意、雇了多少人。

税务衙门知道：150 个字段的含义、税率阶梯、抵扣规则。

老陈不再让管家填 150 个格子（那是衙门自己该知道的事），而是**重新设计了表单，只问管家知道的事**：

> "你的主人做什么？和谁交易？今年盖了什么？"

三个问题。管家全能回答。而凭这三个答案，老陈的衙门可以自动填好剩下的 147 个格子。

他的洞察是：**问你要不到的上下文，而不是让对方面对你该做的决定。**

---

多年以后，有旅人问诺拉，集市到底变了什么。

"看起来什么都没变。摊位还在，货物还在。但**界面**搬了。以前它夹在买主和我之间。现在，它夹在他们的管家和我的管家之间。"

她顿了顿。

"这座城市里最好的商人悟到了一件事：签字付钱的，未必是走进店门的人。所以你要像当年为签字的人精心布置店面一样，为走进店门的人精心设计一切。"

---

## 💡 概念解析：为 Agent 设计产品（Designing for Agents）

这则寓言讲的是 Teddy Riker（Ramp）提出的"Agent-First Design"理念。

核心转变：**二八法则已经反转。** 过去 80% 的软件交互由人类直接完成，现在 80% 将通过 AI Agent 完成。产品经理和工程师需要像当年为人类用户精心设计 UI 一样，为 AI Agent 精心设计交互接口。

故事中的三个隐喻对应三大设计原则：

1. **教会 Agent 成功**（诺拉的标签）：不要让 Agent 猜测你的产品规范。像 Notion 在工具描述中主动推送 Markdown 规范一样，直接告诉 Agent 它需要知道的一切。反面教材是 Slack——Agent 默认用标准 Markdown，导致格式全错，用户修格式的时间比自己写还长。

2. **建立反馈循环**（香料商的意见箱）：通过 rationale 参数让 Agent 解释每次调用的原因，通过专用反馈工具收集 Agent 的困惑。Agent 的反馈比人类用户更具体、更一致——它们能直接告诉你下一步该造什么功能。"突然之间，你的 AI 智能体开始告诉你的 AI 智能体：接下来到底该构建什么。"

3. **留意上下文缺口**（老陈的新税表）：不要把你知道的 150 个决策字段甩给对方。反过来，问对方知道什么（"你主人做什么生意？"），然后自己补全剩余信息。设计的是**上下文交换**，不是数据交换。

最终，交互界面从"用户↔软件"变成了"用户的 Agent↔软件的 Agent"。两个 LLM 协作服务同一个用户。谁在这场转变中认真打磨细节，谁就能赢得下一个十年的市场份额。
