📖 每日工程寓言 — 设计循环，不要掌舵

## 陶匠与盲考官

青瓷镇的陈师傅是远近闻名的陶艺大师。他有七十二个徒弟，每人每天要烧一只碗。

陈师傅的教授方式极其精细：他会站在每个徒弟身后，看着他们揉泥、拉坯、修坯，每一步都要纠正。"泥太湿了""转盘太快了""碗壁再薄一分"。从早到晚，他不停地穿梭在七十二个工作台之间，嗓子喊哑了，腿也站肿了。可奇怪的是，徒弟们做得并不好——他们只会模仿陈师傅的动作，却理解不了为什么要这样做。陈师傅一不在，大家就手忙脚乱。

更糟的是检验环节。每天出窑后，陈师傅让每个徒弟自己检查自己的碗。徒弟们拿起自己的作品，翻来覆去看了又看，最后都说："师傅，这只碗很完美。"——哪怕是碗底有一条明显的裂纹。

陈师傅很困惑。他拿着那只裂了缝的碗问徒弟："你没看见这条缝吗？"

徒弟红着脸说："看见了……但是我觉得这是窑火不均匀造成的，不是我手法的问题。"

陈师傅叹了口气。他突然明白了：**当你亲手做了一样东西，你就不再是合格的评判者了。**你会为每一个瑕疵找借口，因为承认它，就等于否定自己的劳动。

于是陈师傅做了一个大胆的改变。

首先，他不再站在徒弟身后手把手地指导了。他在每个工作台旁边放了一盆清水和一个木框——标准的检验工具。徒弟做完碗后，先把碗放入水中，如果冒气泡就说明有裂纹；再把碗放进木框里，如果放不进去就说明尺寸不对。这些反馈机制不关心你是谁、你怎么做的，它们只关心结果。

其次，他把验收流程彻底改了。每天出窑的七十二只碗全部打乱顺序，编号后放在暗室里，由一位从隔壁镇请来的老陶匠——他完全不认识任何一个徒弟——按照统一的标准逐一检验。老陶匠不知道哪只碗是谁做的，也不在乎烧制过程有多辛苦，他只看碗本身：圆不圆、薄不薄、有无裂纹、釉色是否均匀。

徒弟们起初很不适应。没人站在身后纠正了，他们常常做错了都不知道。但渐渐地，奇迹发生了。出了错的人通过检验工具立刻知道自己哪里有问题，下一只碗就改进了。他们不再等陈师傅来告诉他们答案，而是自己摸索、自己修正。有人发现拉坯时手腕的角度影响碗壁的均匀度，有人找到揉泥时含水量和开裂的关系。这些发现不是陈师傅教出来的——是在循环的反馈中自己长出来的。

三个月后，青瓷镇的碗品质翻了三倍。而陈师傅呢？他每天只需要坐在茶室里喝喝茶，偶尔校准一下检验标准。七十二个徒弟在七十二条反馈循环里自行运转，不需要他掌舵。

只有一件事他绝不妥协：**评判者必须和制作者彻底隔离。**只要老陶匠哪怕知道一只碗是谁做的，公正性就开始崩塌——不是因为他想偏袒，而是因为人的大脑天生会为"自己人"的失败找理由。

💡 **概念解析：设计循环，不要掌舵（Design Loops, Don't Steer）**

这是 Anthropic 工程师 Lance Martin 在 2026 年提出的 AI 交互范式转变。核心论点是：当 AI 模型能力足够强（如 Mythos 级模型）时，人类的角色应从"逐轮操控"转向"设计反馈循环"。

旧模式是人类充当方向盘——每一步都在修正方向，效率低且不可扩展。新模式是人类设计一个闭环：定义目标、设立独立的检验标准、让模型在循环中自我迭代。Anthropic 的两个实现是 **/goal**（定义完成标准后让 agent 自主工作）和 **Outcomes API**（用 rubric 评分标准驱动 agent 迭代）。

其中最关键的工程洞察是**评分器隔离（Grader Isolation）**：评判 agent 工作质量的评分器必须运行在独立的上下文窗口中。如果评分器和执行 agent 共享上下文，agent 在实现过程中产生的偏见、假设和"故事"会污染评分结果——就像徒弟检查自己的碗一样，天然倾向于为自己的错误找借口。用独立窗口确保评分器只看到客观结果，不看过程，从而打破自我确认偏差的循环。

这套思路呼应了 Peter Steinberger 的名言："你不应该再手把手地 prompt coding agent 了，你应该设计让 agent 自己 prompt 自己的循环。"
